# Product Grid Format — Implementation SOP

## Reference examples (look here first)

They sit in the shared `../files/` store, matched by the `vf=product-grid` token. **Study one first** — notice how uniform the cells are and how the full grid reads as one complete set.

## What this format is

A static built as a **uniform grid of cells, each isolating one product, SKU, or variant**, so the whole range snaps into a single satisfying set. It works because a complete, orderly lineup signals range and abundance, and lets a viewer take in a whole collection in one scroll-stopping frame.

Strongest for **multi-SKU ranges, collections, sets and bundles**, and for the single-product play where the *same* product repeats per cell and a **label** carries the difference (days of the week, moods, occasions, use-cases).

The one property to protect: **the cells read as one clean, complete, interchangeable set.**

## Inputs

Expect the **SKU/variant lineup** (or the single product plus the labels to swap per cell), clean isolated product shots, and any per-cell labels or prices. The messaging angle decides what the set is framed to prove (range, value, personalization); this SOP governs the grid.

## Anatomy

1. **Title:** the collection, set, or offer name.
2. **The grid:** uniform cells, one product each, consistent framing, scale, and background.
3. **Per-cell label (optional):** name, price, day, mood, or use-case.
4. **Payoff:** brand lockup and/or the offer.

## Build rules (priority order)

1. **Keep the cells uniform** — same crop, scale, lighting, and background — so the set reads as one.
2. **One product or variant per cell.** Do not mix in lifestyle shots or text tiles; that turns it into a bento-grid.
3. **Show enough to feel complete.** A filled 3x3 or 3x4 reads as "the whole range."
4. **If one product repeats, let the label do the swapping** (days, moods, occasions) so each cell still earns its place.
5. **Consistent gutters and alignment.** The order and rhythm are what make it satisfying.
6. **Honest claims.** Validate any prices or discounts; no absolutes or banned phrases.

## Spec caps

| Element | Guide |
|---|---|
| Cells | ~6-12 (a full 3x3 / 3x4 reads as complete) |
| Content per cell | one product/variant only |
| Per-cell label | short (name, price, or one word) |
| Text | title + labels only; no paragraphs |

## Build steps

1. Read the brief: the lineup (or the single product + swap labels) and what the set should prove.
2. Lock a uniform cell treatment (crop, scale, background) and apply it to every product shot.
3. Lay out the grid; fill enough cells to feel like the complete set.
4. Add per-cell labels if the concept needs them (variant name, price, day, mood).
5. Add the title and brand/offer lockup.
6. Claims pass (validate prices/discounts).
7. Deliver: layout, cell treatment spec, labels, title, end lockup, claims flags.

## QA checklist
- [ ] Every cell isolates one product/SKU/variant with uniform crop, scale, and background
- [ ] No lifestyle tiles or text panels living inside the grid (else it's bento-grid)
- [ ] The grid is filled enough to read as a complete set
- [ ] Labels (if used) are short and consistent
- [ ] Prices/claims validated; no absolutes/banned phrases
