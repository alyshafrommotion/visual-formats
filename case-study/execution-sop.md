# Case Study Format — Implementation SOP

## Reference examples (look here first)

They sit in this same folder, next to this SOP. **Open the folder and study the example first** — how the study framing, result rows, images, and method footnote work together.

## What this format is

A static that presents itself as evidence from a study: a "clinically studied / visibly proven" headline, several result rows each pairing a stat with a supporting image (before/after, product-in-use), grounded by a method footnote. It works because it reads as rigorous, third-party-style proof rather than a claim.

Strongest for **clinically-backed, results-driven products and skeptical, proof-hungry audiences.**

The one property to protect: **it must read as a credible study** — real results, real method, or it backfires.

## Inputs

Expect a **messaging angle**, the **real study results** (stats + method + citation), and supporting images per result. The angle picks the lead result; this SOP governs the proof layout.

## Anatomy

1. **The proof headline:** "Clinically Studied, Visibly Proven" style.
2. **Result rows (2–4):** each a stat + a supporting image + a short claim.
3. **The method footnote:** who was studied, how long, sample size, citation.
4. **Brand + CTA.**

## Build rules (priority order)

1. **Frame it as a study** and back it with a real method footnote. Never fake a study.
2. **Each result pairs a stat with an image** so the proof is shown, not just stated.
3. **2–4 results** — enough to feel rigorous, not a wall.
4. **Method/citation always present.** This is what separates it from `statistic`.
5. **Legible at thumb size; images real** (no misleading before/after).
6. **One CTA. No absolutes / banned phrases.**

## Length caps

| Element | Cap |
|---|---|
| Headline | ≤6 words |
| Result rows | 2–4 |
| Result claim | ≤10 words + stat |
| Method footnote | 1 short block |
| CTA | 1 |

## Build steps

1. Read the brief: angle, the study results, method, citation.
2. Write the proof headline.
3. Build 2–4 result rows (stat + image + short claim each).
4. Add the method footnote (who/how long/sample/citation).
5. Add brand and one CTA.
6. Claims pass (results and method real and sourced; images honest).
7. Legibility check at thumb size.
8. Deliver: headline, result rows, method footnote, CTA, claims flags.

## QA checklist
- [ ] Framed as a study with a real method footnote
- [ ] 2–4 results, each stat paired with a supporting image
- [ ] Citation/method present (distinguishes from statistic)
- [ ] Images honest; one CTA; numbers validated; no absolutes/banned phrases
