# High-Craft Edit Format — Execution SOP

For "is this ad a High-Craft Edit?" naming/classification questions, use `classification.md` in this same folder instead. This document is for building and scripting one.

## Reference examples (look here first)

Example media lives in the shared `../files/` store, matched by the format token: all High-Craft Edit examples are files containing `vf=high-craft-edit`. **Start with `b=mous_vf=high-craft-edit.mp4`** and watch how every claim gets its own built payoff (drop test, crane-drop, exploded-view animation, magnet hang, meme insert) and how each one tries to top the last.

## What this format is

A voiceover drives a fast montage and **the editing does the entertaining**: nearly every beat carries a purpose-built visual payoff — a staged stunt, a built animation, a meme/reaction insert, or a dramatized demo — and the payoffs escalate so a dense, feature-packed script stays fun to watch. It is **always a video**. The edit is the hero.

Strongest for: **feature-heavy or spec-heavy products, durability/quality claims you can stage, "here's everything it does" rundowns, and any script that would be boring shot flat but comes alive when every line gets its own visual gag.**

The one property to protect: **every beat earns a built payoff, and each one tops the last.** The moment the edit coasts on plain product shots or a static talking head, it stops being this format.

## Inputs

Expect a **messaging angle** (the argument), persona and awareness stage, the **VO/script**, and a **payoff list**: for each beat, the specific built visual that dramatizes it and which kind it is (staged stunt, animation/motion-graphic, meme/reaction insert, or dramatized demo). Staged claims must be honest — a drop test has to show a real result, not a faked one.

## Anatomy — the layers

### 1 · The VO (spine)
- A tight, high-energy voiceover carries the argument and sets the pace. Written first.
- It can be a presenter on camera at times, but the presenter is not a held anchor; the edit cuts away to the payoffs constantly.

### 2 · The payoff layer (the show)
- One built visual payoff per beat, cut tightly to the line.
- **Vary the kind** so it never feels like one gimmick: staged stunt, built animation, meme/reaction insert, dramatized demo.
- **Escalate:** each payoff should feel like it's topping the last, especially across a long rundown.
- Legible fast — the gag reads in ~1–2s at thumb size.

### 3 · Sound design
- Impacts, whooshes, clicks, and hits synced to the cuts. The sound sells the craft as much as the picture.

## Script / build rules (priority order)

1. **Write the VO first,** then assign one built payoff per beat.
2. **Every beat earns a built payoff** — stunt, animation, insert, or dramatized demo. Cut any beat that can only be a plain product shot, or make it earn a gag.
3. **Vary the payoff type** across the ad (stunt / animation / insert / demo) so it doesn't feel like one repeated trick.
4. **Escalate the craft** — order beats so payoffs build, and save a big one (a crane-drop, a hero stunt) for late.
5. **Cut to the VO beat** — momentum comes from the edit changing on the line, with sound design punching each cut.
6. **Staged claims stay honest** — a stress test shows the real result; animations of internal parts match the real build. No faked outcomes.
7. **Brand/product is the throughline,** but let the payoffs carry it; the CTA lands at the end.
8. **Banned:** flat stretches with no payoff, one repeated gimmick, faked stunt results or fabricated internals, absolutes.

## Length caps

| Element | Cap |
|---|---|
| Hook (first payoff) | ≤3s |
| Beats | 6–20+, each with its own built payoff |
| Total runtime | 20–90s (this format sustains longer than most because the edit keeps it alive) |
| Payoffs per beat | 1 (occasionally a fast cluster) |
| Repeated payoff type back-to-back | avoid; rotate the kind |

## Build steps

1. Read the brief: angle, persona, awareness stage.
2. Lock the VO/script; break it into beats.
3. For each beat, design one built payoff and label its type (stunt / animation / insert / demo).
4. Order the beats so the payoffs escalate; place a hero payoff late.
5. Confirm any staged claim is honest and any internal animation matches the real build.
6. Storyboard payoff entrances timed to the exact line each dramatizes; spec the sound-design hit per cut.
7. Claims pass: every on-screen stat/quote/stunt result sourced and validated.
8. Production handoff: dense cut list, one payoff per beat, sound design synced, captions on.
9. Deliver: VO by beat, the payoff + type per beat, the escalation order, the hero payoff, sources/claims flags, and a secondary format tag if one applies (e.g. demo, listicle).

## QA checklist
- [ ] It's a video; a VO drives the pace and the visuals are cut to it
- [ ] Nearly every beat has its own built payoff (stunt / animation / insert / demo)
- [ ] Payoff types are varied, not one repeated gimmick
- [ ] The payoffs escalate; a hero payoff lands late
- [ ] Sound design punches the cuts
- [ ] Staged claims are honest; internal animations match the real build; nothing fabricated
- [ ] No flat stretches coasting on plain product shots or a static talking head
- [ ] Brand carried through; CTA at the end
- [ ] Secondary format tagged if the ad also does something else (e.g. demo, listicle)
- [ ] Plays legibly at thumb size
