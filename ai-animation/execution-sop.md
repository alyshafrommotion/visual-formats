# AI Animation Format — Implementation SOP

## Reference examples (look here first)

- **Reference examples:** They sit in this same folder, right next to this SOP.

**Whenever this SOP is triggered, open this folder and study the example first** — the character design, the mascot, how the story arc is paced, and how VO + on-screen text carry the message.

## What this format is

A fully AI-generated animated video that tells a short narrative with an animated character (often plus a mascot), instead of live-action footage. It works because animation makes the problem exaggeratable and charming, the mascot personifies the product, and AI generation makes a "produced" look cheap and fast to iterate.

Strongest for **story-driven problem→solution arcs, personifying the product, whimsical/lighthearted brands, and testing many narrative variants cheaply.**

The one property to protect: **a consistent animated character and a clear story arc** — AI animation without a coherent character or narrative just looks like drifting generative noise.

## Inputs

Expect a **messaging angle** (the story/argument), persona and awareness stage, the **problem→solution narrative**, product truth/claims, and any brand character/mascot direction. The angle sets the story; this SOP governs the animated build.

## Anatomy — the beats

- **Problem (exaggerated):** the animated character living the pain, dialed up for charm.
- **Discovery:** the character finds the product; the mascot can enter here.
- **Benefits:** the product's real benefits, shown as the character's relief.
- **Lifestyle montage:** the character thriving across settings.
- **Resolution + CTA:** confident payoff and a clear shop prompt.

## Build rules (priority order)

1. **Consistent character.** Keep the protagonist (and mascot) visually stable across scenes — drift breaks the story.
2. **Story arc first.** Problem → discovery → benefits → lifestyle → CTA. The animation serves the narrative.
3. **Mascot personifies the product** when used; keep it on-brand and consistent.
4. **VO + on-screen text carry the message;** the animation shows the feeling.
5. **Exaggerate the problem, not the claims.** Visual hyperbole is fine; product claims stay true.
6. **Specificity is credibility.** Real benefits, real numbers. No absolutes.
7. **One CTA,** as the resolution.
8. **Banned:** inconsistent/morphing characters mid-story, unreadable text, fabricated claims, "designed to," "seamless," absolutes.

## Length caps

| Element | Cap |
|---|---|
| Hook (problem) | first 3s |
| Total runtime | 20–45s |
| On-screen text lines | short, ≤12 words |
| Brand/product mentions | woven into the story; 1 clear CTA |

## Build steps

1. Read the brief: angle, persona, awareness stage; lock the narrative arc.
2. Define the character + optional mascot and keep references for consistency.
3. Write the VO script beat by beat (problem → discovery → benefits → lifestyle → CTA).
4. Storyboard the scenes; note the on-screen text per beat.
5. Generate/animate with consistent character references.
6. Claims pass (validate every number; keep product claims true).
7. Deliver: VO script by beat, scene/storyboard list, on-screen text, character/mascot notes, CTA, claims flags.

## QA checklist
- [ ] It's a fully AI-generated animated video (no live-action lead)
- [ ] Character (and mascot) stay consistent across scenes
- [ ] Clear problem → discovery → benefits → lifestyle → CTA arc
- [ ] VO + on-screen text legible and on-message
- [ ] Problem exaggerated but claims true; numbers validated
- [ ] One CTA as the resolution
