# Us Vs Them Format — Implementation SOP

## Reference examples (look here first)

- **Brain location:** `/agent/brain/2. ideation/visual-formats/us-vs-them/`
- This SOP lives in that folder, so the example creatives sit next to it.

**Whenever this SOP is triggered or referenced, open that folder and study the examples first** — how many rows, how the two columns are labeled, and whether "them" is a named competitor or "the old way."

## What this format is

A two-column comparison: the brand on one side with green checks, the alternative (a named competitor, a category, or "the old way") on the other with red X's. It works because it makes the decision feel binary and pre-frames the buyer to the brand's criteria — you win by choosing which rows the comparison is fought on.

Strongest for **differentiation, switching/replacement angles, category reframes, and skeptical/comparison-shopping audiences.** Requires **true, defensible contrasts** — this is the highest-scrutiny format for claims.

The one property to protect: **every row must be true and fair for both columns.** An overreaching or dishonest comparison is a legal risk and a trust-killer; screenshots of a rigged table circulate.

## Inputs

Expect a **messaging angle** (the winning contrast), persona and awareness stage, the **product catalog + competitor facts + claim flags**, and VOC on what buyers actually compare. The angle picks the frame; the facts make it defensible; this SOP governs the columns and rows.

If the contrasts aren't verifiable for both sides, stop and verify. Never invent a competitor weakness.

## Anatomy — the layers

### 1 · The frame / headline
- Sets the comparison and the criteria: "This Instead of That," "[Brand] vs [Old Way]: which actually works?" Names the lens the buyer should judge on.

### 2 · The two columns
- **Us** (brand) with checks; **Them** (competitor / category / old way) with X's. Clear column labels.
- Deciding who "them" is: a **named competitor** raises scrutiny and legal exposure but hits harder; **"the old way"/category** is safer and still effective. Choose from the brief and the claim flags, not by default.

### 3 · The rows (the format)
- 4–7 comparison rows, each a single criterion the persona cares about. Ordered strongest-first.
- Each row is one buyer-language attribute (not an internal spec), true for both sides.

### 4 · The verdict / CTA
- A short closing line and a quiet CTA. The table already argued; the line just lands it.

## Craft rules (priority order)

1. **Every row true and fair for both columns.** If you can't defend "them's" X, cut the row.
2. **Pick the rows you win cleanly,** ordered by what the persona cares about, strongest first.
3. **Buyer-language criteria,** not engineering specs. "No 3pm crash" beats "sustained-release matrix."
4. **One criterion per row.** No row bundles two attributes.
5. **4–7 rows.** Fewer than 4 feels thin; more than 7 stops being read.
6. **Specificity is credibility.** Real attributes, real numbers where used. No absolutes ("works with everything").
7. **Naming a competitor is a claims decision,** not a creative one — only with legal/claim-flag clearance. Otherwise use "the old way"/category.
8. **Banned:** unverifiable "them" X's, invented competitor weaknesses, "designed to," "seamless," absolutes, and rows the brand doesn't actually win.

## Length caps

| Element | Cap |
|---|---|
| Headline | ≤9 words |
| Column labels | ≤4 words each |
| Each row | ≤6 words per side, one criterion |
| Rows | 4–7 |
| Verdict/CTA | ≤8 words |

## Build steps

1. Read the brief: angle, persona, awareness stage.
2. Pull product facts, competitor facts, and claim flags; verify both sides of every candidate row.
3. Decide who "them" is (named competitor vs old way/category) per claim-flag clearance.
4. Select 4–7 rows the brand wins cleanly; order strongest-first in buyer language.
5. Write the headline (the criteria lens) and the verdict line.
6. Claims pass: every row defensible for both columns; every number validated; competitor naming cleared.
7. Design handoff: clean two-column table, clear check/X system, legible labels, strongest row on top.
8. Deliver: headline, column labels, ordered rows (both sides), verdict/CTA, claims flags + competitor-naming clearance note.

## QA checklist
- [ ] Every row is true and fair for both columns
- [ ] Rows are buyer-language criteria, one per row, strongest first
- [ ] 4–7 rows; brand wins each cleanly
- [ ] "Them" choice (named vs old way) matches claim-flag clearance
- [ ] Every claim/number validated; no absolutes; no invented weaknesses
- [ ] Table legible at thumb size; verdict lands
