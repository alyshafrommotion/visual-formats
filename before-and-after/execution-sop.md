# Before And After Format — Implementation SOP

## Reference examples (look here first)

They sit in this same folder, next to this SOP. **Open the folder and study the example first** — how the pair is framed, labeled, and supported by a stat/review.

## What this format is

A static or video whose hero is a single before→after transformation of the same subject, showing the change the product drives, usually backed by a stat, review, or study line. It works because a visible transformation is the most direct proof there is — the viewer sees the result, not just a claim.

Strongest for **results-driven products (hair, skin, body, home), problem-aware and skeptical audiences, and proof-hungry mid-funnel.**

The one property to protect: **the before/after must be honest and clearly the same subject** — misleading or mismatched pairs destroy trust (and violate platform/claims rules).

## Inputs

Expect a **messaging angle**, a real before/after asset (same subject, honest timeframe), and any supporting stat/review/study. The angle sets the promise; this SOP governs the proof layout.

## Anatomy

1. **The transformation pair:** before and after of the same subject, clearly labeled, with the timeframe.
2. **The promise line (hook):** the payoff the transformation proves.
3. **The support:** a stat, review badge, or study footnote reinforcing it.
4. **Brand + CTA + results disclaimer.**

## Build rules (priority order)

1. **Honest, same-subject pair.** Real before/after, clearly the same person, honest timeframe. Never fake or mismatch.
2. **Label before / after and the timeframe** so the comparison is unambiguous.
3. **The pair is the hero** — keep copy from crowding it out.
4. **One promise line** the transformation proves.
5. **Support with a real stat/review/study** and a "results may vary" disclaimer.
6. **One CTA. No absolutes / banned phrases.**

## Length caps

| Element | Cap |
|---|---|
| Promise line | ≤8 words |
| Support line | 1 (stat/review) |
| Pairs | 1 hero pair (a montage of several is a video variant) |
| CTA | 1 |

## Build steps

1. Read the brief: angle, the before/after asset, timeframe, support.
2. Confirm the pair is honest and same-subject; label before/after + timeframe.
3. Write the promise line the transformation proves.
4. Add the support (stat/review/study) and a results disclaimer.
5. Add brand + one CTA.
6. Claims pass (transformation honest; numbers validated; disclaimer present).
7. Legibility check at thumb size.
8. Deliver: pair note, promise line, support, disclaimer, CTA, claims flags.

## QA checklist
- [ ] Honest, same-subject before/after, labeled with timeframe
- [ ] The pair is the hero; promise line ≤8 words
- [ ] Real supporting stat/review/study + results disclaimer
- [ ] One CTA; claims validated; no absolutes/banned phrases
