# Line Chart Format — Implementation SOP

## Reference examples (look here first)

- Example media lives in the shared `../../files/` store, matched by the `vf=line-chart` token in the filename.

**Whenever this SOP is triggered, pull the `vf=line-chart` examples first** — study how the curve is drawn, how few data points do the work, and where the one turning-point annotation lands.

## What this format is

A static built around a plotted line/trend graph that makes an abstract mechanism or an outcome instantly legible: the viewer *sees* the signal the product tracks, or the trajectory it delivers, as one clean curve over a progression axis (time, cycle, usage). It works because a line reads as data/proof and turns "how does this work / does this work" into a picture you get at a glance.

Strongest for **products whose value is a measurable change over time or a data-driven mechanism** — tracking, biometrics/health, progress, growth, savings.

The one property to protect: **the curve tells the story on its own** — one clear trend and one turning point the reader gets in under a second.

## Inputs

Expect a **messaging angle**, persona, and the **real signal/metric** the graph will plot (what it is, its units, and the trend or turning point that matters). The angle picks the argument; the metric is the line; this SOP governs how the graph is built.

## Anatomy

### 1 · The headline (the hook)
- Names the payoff or mechanism the graph proves ("Track your fertility in your sleep").

### 2 · The line/curve (the hero)
- One plotted trend across a progression axis (time/cycle/usage). Single series.

### 3 · Data points + annotation
- A few labeled points (real values/units) and **one** turning-point callout that carries the meaning.

### 4 · The scene
- A lifestyle or product shot behind/around the graph that grounds context and use, without fighting the line.

### 5 · The CTA
- One clear next-step prompt.

## Build rules (priority order)

1. **One curve, one story.** A single trend line, not a cluttered multi-series chart.
2. **One turning point, annotated clearly.** The moment that matters gets a callout; everything else supports it.
3. **Real, specific data.** Plausible values and units, not decorative squiggles. No invented results.
4. **Legible at thumb size.** Bold high-contrast line, few labels, generous type.
5. **Tie the curve to the mechanism or the result** the buyer cares about, not a vanity metric.
6. **The scene supports the chart**, it doesn't compete with it.
7. **One CTA.**
8. **Banned:** fake/implausible data, multi-line spaghetti charts, unreadable micro-labels, absolutes, "designed to," "seamless."

## Length caps

| Element | Cap |
|---|---|
| Headline | ≤8 words |
| Plotted points | 3–7 |
| Point label | value + unit only |
| Annotations | 1 turning-point callout |
| CTA | 1 |

## Build steps

1. Read the brief: the mechanism or result to show, persona, the real metric and its units.
2. Write the headline first — the payoff the curve proves.
3. Design the single curve and its progression axis (time/cycle/usage).
4. Plot 3–7 real data points with value labels.
5. Add one turning-point annotation at the moment that matters.
6. Place it over a supporting lifestyle/product scene.
7. Claims pass (validate every plotted number; no invented results).
8. Design handoff: legible at thumb size, bold line, minimal labels.
9. Deliver: headline, the plotted curve spec (points + units + annotation), scene direction, CTA, claims flags.

## QA checklist
- [ ] One single-series curve is the hero
- [ ] Progression axis is clear (time/cycle/usage)
- [ ] 3–7 real, plausible data points with units
- [ ] Exactly one turning-point annotation carries the meaning
- [ ] Legible at thumb size; scene supports, doesn't fight the line
- [ ] One CTA; all numbers validated; no absolutes/banned phrases
