# Instagram Comment Format — Implementation SOP

## Reference examples (look here first)

Real, live-in-market examples of this format are saved in the brain alongside this SOP:

- **Reference examples:** They sit in this same folder, right next to this SOP.
- This SOP lives inside that same `instagram-comment/` folder, so the example creatives are the image files sitting next to it.

**Whenever this SOP is triggered or referenced, open this folder and study the example images before writing.** Calibrate the comment styling, who is speaking, and how the brand replies (or whether it replies at all) against what the examples actually do.

## What this format is

A static whose hero is a screenshotted Instagram (or TikTok/Facebook) comment. The comment is the hook: a real person reacting, praising, doubting, or asking. It works because the viewer trusts a bystander's words far more than the brand's, and because a comment UI reads as found footage, not paid media.

Two modes, decided by the brief:
- **Standing comment (social proof):** one strong comment (or a small stack) carries the whole ad. No brand reply needed. Best for warm audiences and testimonial angles.
- **Comment + brand reply (objection handling):** a skeptical or curious comment on top, the brand's human reply underneath. Best for a known objection or a feature the angle wants to argue.

The one property to protect: **the comment must read like a person typed it in the app**, not like a review the brand curated.

## Inputs

This SOP executes; it doesn't strategize. Expect a **messaging angle** (what the ad argues), persona and moment context, and whatever VOC the project holds (reviews, real comment scrapes, call transcripts, DMs). The angle decides what the comment is about; this SOP governs how it's built.

If no VOC exists, say so and gather real language first. The comment is mined, not invented — a fabricated-sounding comment is worse than no ad.

## Anatomy — the layers

### 1 · The comment (hero)
- Real IG comment chrome: username + avatar, the comment text, like count, "Reply", relative timestamp (2d, 1w). Keep it believable, not pristine.
- 1–2 sentences, typed register: lowercase starts, contractions, one emoji at most, the occasional dropped punctuation. If it reads grammatically perfect, it reads fake.
- The comment does the targeting. Written in the persona's own words so the right person feels seen and the wrong person scrolls.
- Username should feel like a real handle (a name plus numbers, a hobby handle), never a brand-adjacent name.

### 2 · The brand reply (only in reply mode)
- Verified brand handle, reply indented under the comment.
- First line reacts to the person, not the topic. No "Great question!" No "We're so glad."
- Human voice: the way a sharp social manager actually replies — warm, specific, a little playful, one concrete fact, no positioning phrase.
- Brand named once. A single CTA-ish nudge is allowed here (this is the brand's turf), but it must sound like a person, not a banner.

### 3 · Background / context frame
- Optional product shot, lifestyle image, or flat color behind the comment card. Keep it quiet; the comment is the star.
- If a product is shown, it's incidental, not staged like a hero render.

## Craft rules (priority order)

1. **Mine, don't manufacture.** Build the comment from a real quote near the angle. If no phrase in it was ever actually said by a person, rewrite it.
2. **Typed register beats written register.** Casual caps, fragments, one emoji, real-handle usernames.
3. **One idea per comment.** A comment argues one thing (a result, an objection, a surprise), never a feature list.
4. **The reply answers the person, not the product.** Verdict or reaction first; the fact second.
5. **Specificity is the credibility.** Real numbers, real timeframes, real product names. Skeptics screenshot absolutes, so never "works for everyone."
6. **Brand named once, mid-reply, the way a person says it.** Two mentions max on product-aware retargets.
7. **Banned:** "Great question," "we're so glad," "designed to," "seamless," "solutions," ™/® inside the comment, and any comment that reads like a pulled review.
8. **Screenshot test:** dropped into a real feed with no context, nothing reads as an ad until the brand handle.

## Length caps

| Element | Cap |
|---|---|
| Comment | 1–2 sentences, ≤22 words, ≤1 emoji |
| Brand reply | 1–3 sentences, ≤35 words, ≤1 emoji |
| Stacked comments (if used) | ≤3, each ≤18 words |

## Build steps

1. Read the brief: angle, persona, moment, awareness stage.
2. Pull 5–10 verbatim VOC lines near the angle; pick the one that carries the argument.
3. Compress it to a typed-register comment; invent a believable handle.
4. Choose mode: standing comment or comment + reply.
5. If reply mode, write the reply — reaction first, one concrete fact, brand named once.
6. Register pass (rules 1–8).
7. Claims pass: every number/claim validated against the project's claim flags.
8. Design handoff: comment card in the top half; realistic UI chrome; quiet background.
9. Deliver: comment text, handle, reply (if any), background direction, claims flags.

## QA checklist
- [ ] Comment reads typed-in-the-app, not curated
- [ ] Username looks like a real handle
- [ ] One idea only; built from a real VOC phrase
- [ ] Reply (if any) reacts to the person before the fact
- [ ] Brand named once; no banned phrases; no absolutes
- [ ] All claims validated
- [ ] Screenshot test passes: nothing reads as an ad before the brand handle
