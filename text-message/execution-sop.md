# Text Message Format — Implementation SOP

## Reference examples (look here first)

They sit in this same folder, next to this SOP. **Open the folder and study the example first** — how the chat feels real, how the pitch is woven in, and how it pays off.

## What this format is

A static built as a screenshot of a text/iMessage conversation, where the pitch plays out as a back-and-forth — a friend recommending the brand, a funny confession, a payment request. It works because a "read over their shoulder" DM feels personal and un-adlike, and a good exchange carries word-of-mouth credibility with humor.

Strongest for **word-of-mouth/recommendation angles, relatable UGC, humor, and problem-aware audiences.**

The one property to protect: **it has to read like a real text thread** — stiff or salesy bubbles break it.

## Inputs

Expect a **messaging angle** and the beat the exchange should land (recommendation, confession, request). The angle carries the message; this SOP governs the thread.

## Anatomy

1. **The contact header** (optional): a name that sets the relationship ("Elma").
2. **The exchange:** natural back-and-forth bubbles building to the point.
3. **The payoff:** the recommendation, punchline, or request (e.g., a payment request bubble).
4. **Optional shared photo** of the product in-thread.

## Build rules (priority order)

1. **Sound like real texting.** Casual, short bubbles, natural rhythm, believable typos/emoji.
2. **Weave the pitch into the story**, don't paste a sales line into a bubble.
3. **Build to one clear payoff** (recommendation / punchline / request).
4. **Keep it skimmable** — a readable number of bubbles, not a novel.
5. **Product shown naturally** (shared photo or named in-thread).
6. **Honest claims. No absolutes / banned phrases.**

## Length caps

| Element | Cap |
|---|---|
| Bubbles | ~6–12, skimmable |
| Bubble | 1–2 short lines |
| Payoff | 1 clear beat |

## Build steps

1. Read the brief: angle, the beat the exchange lands.
2. Set the relationship (contact header if useful).
3. Write the exchange to feel real and build to the payoff.
4. Add a shared product photo or natural mention.
5. Format as believable iMessage bubbles.
6. Claims pass (any claim honest; validate numbers).
7. Legibility check at thumb size.
8. Deliver: thread script, contact header, product moment, payoff, claims flags.

## QA checklist
- [ ] Reads like a real text thread (casual, natural rhythm)
- [ ] Pitch woven into the story, not pasted in
- [ ] Builds to one clear payoff; skimmable bubble count
- [ ] Product shown naturally; claims honest; no absolutes/banned phrases
