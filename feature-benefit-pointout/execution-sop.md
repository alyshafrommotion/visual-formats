# Feature Benefit Pointout Format — Implementation SOP

## Reference examples (look here first)

- **Reference examples:** They sit in this same folder, right next to this SOP.
- This SOP lives in this folder, so the example creatives sit next to it.

**Whenever this SOP is triggered or referenced, open this folder and study the examples first** — label count, where the lines point, and how each caption turns a spec into an outcome.

## What this format is

A hero product on a clean or lightly styled background, with 3–6 short call-outs connected by thin lines or arrows to specific parts of the product. Each call-out names a feature and, in the same breath, the benefit it delivers. It works because it makes an unfamiliar product legible in one glance and pre-answers "what do I actually get."

Strongest for **considered, feature-rich, or visually interesting products** where the value isn't obvious from a photo alone (devices, tools, formulations, apparel with tech, packaging with a mechanism).

The one property to protect: **every label ends on the benefit, not the spec.** "612mg dose" is a spec; "612mg dose — the potency studies actually used" is a pointout.

## Inputs

Expect a **messaging angle** (which benefits matter to this buyer), persona and awareness stage, the **product catalog / claim facts**, and any VOC that tells you which features people actually care about. The angle and VOC decide which 3–6 features earn a label; the catalog supplies the true specs; this SOP governs layout and phrasing.

If specs or claims aren't verified, stop and get them — this format lives or dies on accurate, screenshot-proof specifics.

## Anatomy — the layers

### 1 · Hero product
- One product, shot clean and legible, angled so the parts you want to label are visible. Real product, not a render that hides the mechanism.
- Enough negative space around it for labels to breathe. Centered or slightly offset.

### 2 · The headline (optional but usual)
- A short frame at the top: the one-line promise the labels prove. 4–9 words. Sets the lens ("Everything that makes it worth it," "Why it costs what it costs").

### 3 · The call-outs (the format)
- 3–6 labels, each a thin line/arrow to the exact feature it describes.
- Structure per label: **feature → benefit**, compressed. Lead with the concrete part, land on the outcome.
- Balance them around the product; alternate left/right so the eye travels the whole frame.
- One idea per label. No label carries two features.

### 4 · Footer (optional)
- A quiet offer, rating, or CTA line. Never competes with the labels.

## Craft rules (priority order)

1. **Every label ends on the benefit.** If a label stops at the spec, it isn't finished.
2. **Point at the real thing.** The line must land on the actual part; a label floating near nothing reads as decoration and kills trust.
3. **Lead with the buyer's language for the feature,** not the internal/engineering name. Translate "hydrolyzed marine collagen" into what it does unless the buyer already shops on that term.
4. **Rank by what the persona cares about,** top to bottom. The first label is the strongest reason, not the first feature on the spec sheet.
5. **Specificity is credibility.** Real numbers, real materials, real timeframes. No "premium," no "high-quality," no absolutes.
6. **3–6 labels, never more.** Past six it becomes a diagram and no one reads it.
7. **Banned:** "premium," "high-quality," "state-of-the-art," "designed to," vague adjectives with no number behind them, and any label that's a feature with no outcome.

## Length caps

| Element | Cap |
|---|---|
| Headline | 4–9 words |
| Each label | ≤10 words, feature + benefit in one breath |
| Label count | 3–6 |
| Footer | ≤8 words |

## Build steps

1. Read the brief: angle, persona, awareness stage, the benefits that matter.
2. Pull the true specs from the product catalog; flag anything unverified.
3. Choose the 3–6 features that map to the persona's top reasons.
4. Write each as feature → benefit, compressed to the cap.
5. Rank labels by importance; assign left/right placement around the product.
6. Write the headline as the promise the labels prove.
7. Claims pass: every spec and number validated against claim flags.
8. Design handoff: product angle that exposes each labeled part; thin lines landing exactly on the part; balanced label placement.
9. Deliver: headline, ordered labels with their target parts, footer, image direction, claims flags.

## QA checklist
- [ ] Every label ends on a benefit, not a spec
- [ ] Every line points at the real, visible part
- [ ] Labels use buyer language, ranked by what the persona cares about
- [ ] 3–6 labels, balanced around the product
- [ ] Every number/claim validated; no vague adjectives or absolutes
- [ ] Headline states the promise the labels prove
- [ ] Reads legible in one glance at thumb size
